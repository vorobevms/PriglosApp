# PriglosApp: сборка macOS из общего проекта

Подготовлено на Windows 13 октября 2026. 14 октября 2026 arm64-приложение и DMG собраны на MacBook. Пользователь вручную подтвердил запуск packaged-приложения, работу интерфейса, отображение дизайнов, загрузку фотографии и сохранение готового приглашения. Intel-сборка на Mac не проверялась.

## Исправление запуска packaged-приложения на macOS

В Electron 38.8.6 packaged-приложение с русским названием завершалось с `EXC_BREAKPOINT / SIGTRAP` при запуске GPU helper. Расшифровка crash report официальными символами показала `ElectronBrowserClient::AppendExtraCommandLineSwitches`: проверка `CHECK_EQ(program, child_path)` отвергала путь helper из-за различий Unicode NFC/NFD в букве `й`.

В `scripts/electron-builder.mac.cjs` только для macOS задан `mac.extendInfo.CFBundleName` в форме NFD, совпадающей с нормализацией файловых путей macOS. Видимое название, runtime-исходники, 15 дизайнов и Windows-конфигурация сохранены. Исправленное приложение успешно запущено из папки сборки и `/Applications`; main, GPU и renderer остаются работающими. Ad-hoc подпись и контрольная сумма финального DMG проверены. Developer ID и notarization не применялись.

## Что подготовлено

- Одни и те же `src/`, конфигурация 15 дизайнов, фоны, встроенный Rubik и обработка фото для обеих платформ.
- Windows: прежние appId `ru.priglos.app`, package name `priglos-app`, productName `Приглашения`, portable x64 и `assets/balloon.ico` сохранены.
- Mac: `scripts/electron-builder.mac.cjs` читает общий `package.json.build`, меняя только имя Mac-приложения, выходную папку и Mac-параметры. Список runtime-файлов единый; референсы, тесты и development-материалы не входят в приложение.
- `assets/balloon.icns` содержит исходный PNG 256×256 с прозрачностью в стандартном ICNS-блоке `ic08`. Пиксели не перерисованы. На Retina качество ограничено разрешением исходной иконки; вид Dock/Finder проверить на Mac.
- arm64 — основная сборка, x64 — отдельная дополнительная. Universal сознательно не выбран: два runtime в одном пакете увеличивают размер, а владельцу Apple Silicon нужна только arm64.
- Electron зафиксирован lock-файлом на 38.8.6, electron-builder — 26.15.3. Electron 38 требует macOS 12 Monterey или новее.

## Перенос на MacBook

Готовая папка исходников: `transfer-mac/PriglosApp/`. Перенесите её целиком на Mac в обычную локальную папку, например `~/Projects/PriglosApp`. Это снимок того же проекта, без отдельной логики. Дальнейшие изменения следует возвращать в общий проект.

В папке находятся `src/`, runtime-ресурсы `assets/`, иконки обеих платформ, `package.json`, `package-lock.json`, build-скрипты, тесты и документация. Нет Windows `node_modules`, `.exe`, `dist`, `release-portable`, результатов тестов или временных файлов. Не переносите эти исключённые папки вручную.

Для повторного экспорта: переместите предыдущую папку `transfer-mac/PriglosApp` в другое место, затем выполните `npm run prepare:mac`. Скрипт намеренно не удаляет и не перезаписывает существующий снимок.

## Команды на Mac

Только для разработчика, выполняющего сборку: Node.js 24 LTS с npm и Xcode Command Line Tools (Apple `codesign`, инструменты сборки). `hdiutil` входит в macOS. Полный Xcode и платный Apple Developer аккаунт для этого локального тестового варианта не нужны. Интернет нужен для восстановления зависимостей и загрузки Mac runtime Electron; само готовое приложение работает локально.

В Terminal из папки проекта:

```sh
npm ci
mkdir -p dist
npm test
npm run build:mac
```

Папка `dist` нужна существующему тесту настроек для временных файлов; она исключена из Git. В проверке на Mac прошёл 21 тест, один тест для других ОС штатно пропущен.

При необходимости Intel-варианта:

```sh
npm run build:mac:x64
```

Ожидаемые результаты текущей версии:

- arm64 DMG: `release-mac/Конструктор приглашений-1.6.0-arm64.dmg`
- arm64 приложение: `release-mac/mac-arm64/Конструктор приглашений.app`
- x64 DMG: `release-mac/Конструктор приглашений-1.6.0-x64.dmg`
- x64 приложение: `release-mac/mac/Конструктор приглашений.app`

DMG включает приложение и стандартный путь копирования в Applications. Конечному пользователю нужны только DMG и обычный Mac; Node.js, npm, Electron и Codex устанавливать не требуется. DMG не является Windows-подобным мастером установки.

## Что Windows сделать не может

Подготовка конфигурации, исходников, ICNS, тестов и переносимой папки выполнена здесь. Текущая реализация DMG electron-builder вызывает Apple `hdiutil`, а тестовая подпись — Apple `codesign`. Готовый DMG и запуск `.app` требуют Mac. Команда `build:mac` на Windows честно останавливается с объяснением, не создавая фиктивный результат.

## Экспорт и пользовательские данные

`src/main.cjs` использует `path.join(__dirname, ...)`, `BrowserWindow.loadFile`, `dialog.showSaveDialog` и Node `fs.writeFile`. Фоны загружаются по относительным URL из `app.asar`. Абсолютных Windows-путей в runtime-исходниках или конфигурации дизайнов нет. Файл JPEG сохраняется в выбранную через системный диалог папку, независимо от положения `.app`/DMG.

Настройки: `path.join(app.getPath('userData'), 'settings.json')`. При сохранённом package name ожидаемый путь на Mac — `~/Library/Application Support/priglos-app/settings.json`; на Windows прежний `%APPDATA%/priglos-app/settings.json`. Фактический путь определяется Electron. Настройки не хранятся внутри `.app` или DMG.

У приложения нет production npm-зависимостей и собственных нативных `.node` модулей. Electron, electron-builder и Playwright являются кроссплатформенными инструментами разработки; их платформенные компоненты восстанавливаются через `npm ci` на Mac. Windows-скрипты старых визуальных тестов/генерации ресурсов не участвуют в Mac runtime и не нужны для сборки.

## Подпись и Gatekeeper

Это локальный development/test вариант без Developer ID и без notarization. `identity: "-"` включает бесплатную ad-hoc подпись кода, нужную для корректной упаковки Apple Silicon; она не подтверждает издателя и не даёт доверия Gatekeeper. Hardened Runtime выключен только в тестовой конфигурации, notarization и публикация выключены. DMG отдельно не подписывается. Защита macOS не отключается и не обходится.

При передаче скачанного приложения Gatekeeper может заблокировать запуск и сообщить, что разработчик не проверен или Apple не может проверить приложение на вредоносное ПО. Поэтому этот вариант не обещает запуск без предупреждений у партнёра. Нужна отдельная проверка скачанной копии на другом Mac.

Для нормального публичного распространения потребуется Apple Developer Program, сертификат Developer ID Application, подпись с Hardened Runtime и подходящими Electron entitlements, notarization через Apple и прикрепление результата (stapling). После этого нужно проверить Gatekeeper на другом Mac. Ничего из платного процесса сейчас не настраивалось.

## Обязательная проверка на MacBook

1. Собрать arm64, проверить `Contents/Info.plist`, имя `.app`, ICNS и ad-hoc подпись; смонтировать DMG и скопировать приложение в Applications.
2. Запустить установленную копию вне исходной папки; проверить все 15 дизайнов, наличие фонов/шрифта и отсутствие ссылок на проект.
3. Проверить загрузку фото, перетаскивание, колесо/кнопки масштаба, центрирование, поворот, сброс угла, все коррекции, Авто и Сброс.
4. Проверить короткое/длинное имя, дату, время, многострочную локацию и сохранение введённых данных при переключении дизайна.
5. Добавить тестовую локацию, закрыть приложение полностью, запустить снова и подтвердить сохранение настроек.
6. Сохранить JPEG через настоящий Mac-диалог в Downloads/Desktop/Documents, проверить имя `ДР_Воробьев Михаил_22 октября_19-40.jpg`, исходное разрешение фона и совпадение с preview.
7. Визуально сравнить системные шрифты и иконку с Windows; проверить отдельно x64 на Intel, если он нужен. До этого подтверждена готовность конфигурации, а не работоспособность на Mac.

### Системные шрифты — известное ограничение

Rubik уже встроен с OFL-лицензией. Остальные используемые имена — Segoe Print, Impact, Comic Sans MS, Arial Narrow, Georgia и generic sans-serif/serif/cursive. Их наличие и метрики на Mac могут отличаться от Windows. Особенно проверить Полосы и Фонарь (Segoe Print), а также дизайны с Impact/Arial Narrow. Generic-шрифты и system-ui также выбираются самой ОС.

Конфигурации шаблонов и fallback-цепочки оставлены без изменений по требованию не менять оформление. Шрифты Windows не копировались в пакет: наличие шрифта на Windows само по себе не даёт права распространять его в Mac-приложении. Если идентичность текста между ОС обязательна, следующим согласованным этапом нужны лицензированные встроенные шрифты либо утверждённые свободные аналоги. Сейчас точное визуальное совпадение на Mac не гарантируется.

## Windows после подготовки Mac

`npm run build` сохранён. Явная команда: `npm run build:win`. Выходной файл: `dist/Конструктор приглашений.exe`. Существующий `release-portable/Конструктор приглашений.exe` не перезаписывается автоматически.

Регрессионная сборка выполнена отдельно: `npm run build:win -- --config.directories.output=dist/windows-macos-check`. Тестовая копия единственного EXE запускается вне проекта через `tests/portable-standalone.cjs` с отдельным профилем и без Node/npm в PATH.

Результат проверки на Windows: 22 автоматических теста прошли; новая portable-сборка успешно запущена из временной папки, все 15 дизайнов проверены с фото, перетаскиванием, масштабом, вращением и коррекциями. Сохранены 15 JPEG с правильными именами и исходными размерами; байты JPEG совпали с полноразмерным canvas preview. Локация сохранилась после полного перезапуска. Ресурсы загружались из распакованного `app.asar`, обращений к исходной папке не было. Все 30 runtime-файлов совпали с предыдущей Windows-сборкой. Старый распространяемый EXE сохранил SHA-256 `D41785A6A51A123752C9D9EF8DD8C58671C902AAA9ECC4CD444A68DD3A974609`.
